Link

Links go places. They are underlined, named by their destination and never pretend to be buttons.

Overview

A link goes somewhere: another page, a section on this page, an email address. It is underlined so colour is never the only cue. The site uses three kinds: inline links in prose (privacy page), standalone links in the header and footer (nav, mailto:), and links styled as buttons for the primary CTA (button covers the look).

Anatomy

  1. TextMakes sense alone; --color-fg-link.
  2. Underline1px, offset 0.15em; 2px on hover.

Responsive behaviour

  • Header nav links hide below 768px; the gold Get notified button remains and the footer repeats the links.
  • Footer links wrap onto several rows with --space-4 gaps and stay ≥ 24px tall.

Theming

Inline links use --color-fg-link (ink-700 on paper, gold-300 on ink in dark mode). Nav and footer links inherit the surrounding text colour so they work on the hero without extra rules.

Accessibility

Role and pattern

Native <a href>. Never a <span> with a click handler; never an <a> without href.

Keyboard

KeyAction
TabMoves to the link.
EnterFollows it.
Shift+F10Context menu (open in new tab) stays available.

Focus

Shared ring with --radius-sm corners; inline links get the ring around the text box.

Labelling

Text alone must say where it goes: "Read the privacy notice", not "click here". External links add <span class="visually-hidden">(opens in a new tab)</span>.

Motion

Underline thickness changes instantly; nothing animates.

Touch

Inline links rely on line height for a 24px target; standalone links in header and footer have --space-4 between them.

Content

  • Link text is the destination or the action: "Privacy", "Use a different email", "Back to HackMission".
  • Do not underline words that are not links; do not link whole sentences.
  • Email addresses are shown as the address itself.
