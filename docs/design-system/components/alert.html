Alert / banner

A message that stays: inline in a form, or as a banner across the page.

Overview

Inline alerts explain a problem or a condition in place: the unsubscribe error, the signup error card. Banners run across the top of a page for site-wide notices (registration closing). Use a toast for transient confirmations.

Anatomy

  1. IconTone icon, aria-hidden.
  2. Title
  3. BodyWith the way forward.

Sizes

States

Server error kept with the typed value (pages/home/error).

Alerts have no interactive states; dismissible ones add a close button.

Responsive behaviour

  • Full width of the column; banners span the viewport with the container inside.

Theming

Tone tokens --color-*-bg/fg/border/icon; the 4px left border carries the tone with the icon.

Accessibility

Role and pattern

role="alert" only when the alert appears in response to an action (the unsubscribe failure); otherwise role="status" or no role.

Keyboard

KeyAction
TabReaches links/buttons inside.

Focus

On failed submit focus moves to the alert (tabindex="-1").

Labelling

Title or first sentence is the message.

Content

  • Title names the situation; body gives the way forward and a human contact for failures.
  • No blame ("You entered…"), no jargon ("500").
