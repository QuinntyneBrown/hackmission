Button

Buttons let people take an action: join the list, watch the intro, unsubscribe. One primary button per view tells them what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use a button when activating it changes something: it submits the signup form, closes the video dialog, unsubscribes an address. Use a link when it only takes the person somewhere, even when it looks like a button (the hero's Get notified is an <a href="#signup"> styled as a button).

  • Primary is ink on paper: the one action the view exists for. Never two per view.
  • Gold is the primary on ink surfaces (hero, video poster, statement) where ink would vanish.
  • Secondary (the base look) is for everything else that is still an action.
  • Ghost sits inside dense surfaces: dialog headers, toasts, table rows.
  • Link looks like a link but behaves like a button; use it for low-emphasis actions in a sentence.
  • Danger is for destructive actions and only appears inside a confirmation step (the unsubscribe page).

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view and by the surface it sits on.

Emphasis from highest to lowest on the paper canvas.
HTML
<button class="btn btn--primary" type="button">Primary</button>
<button class="btn" type="button">Secondary</button>
<button class="btn btn--ghost" type="button">Ghost</button>
<button class="btn btn--link" type="button">Link</button>
<button class="btn btn--danger" type="button">Danger</button>

Gold on ink

On the hero and other ink surfaces the primary becomes gold; ghost buttons inherit the hero text colour.
HTML
<section class="hero">…<button class="btn btn--gold btn--lg" type="submit">Notify me</button></section>

With icons, icon-only, block

Icon-only buttons carry aria-label; the icon itself is aria-hidden.

Sizes

Medium is the default. Small lives in the site header and toasts; large is for the hero signup and CTA bands where the button is the whole point.

Heights: --control-height-sm/md/lg; padding: --space-3/4/6; font: --font-size-sm/md/lg. In the hero signup, inputs and buttons also get min-height: var(--target-comfortable) (44px).

States

Pointer and focus states are forced with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible, :active, :disabled and aria-busy.

Both themes

  • Loading keeps the width, hides the label behind a spinner, sets aria-busy="true" and ignores clicks (pages/home/submitting).
  • Disabled uses the native attribute, 50% opacity, not focusable. Prefer leaving a button enabled and explaining the problem on activation.
  • Pressed toggle buttons use aria-pressed; see button group.

Responsive behaviour

  • Below 640px the hero signup stacks: the input then the gold button, each full width (.signup__row).
  • Dialog footers keep buttons on one row and wrap when narrower than their combined width; the primary stays last.
  • Medium and large buttons already exceed 44px; small buttons (32px) only appear beside other targets with 8px between them.
  • Labels never truncate; a label that wraps at 360px is too long. Shorten the verb phrase.

Theming

The button reads four component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover) that each variant overrides from semantic tokens. In light the primary is ink on paper; in dark the accent flips to gold with ink text, so .btn--primary and .btn--gold look alike in dark mode. Gold is fixed in both themes because it always sits on ink.

/* Re-skin primary buttons for a partner theme without touching .btn */
[data-theme="partner"] .btn--primary { --btn-bg: var(--color-accent); --btn-fg: var(--color-fg-on-accent); }

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" in the signup form). A link styled as a button stays an <a href>. No ARIA role is needed. WAI-ARIA APG: Button.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up so a mis-press can be cancelled.
EscNo effect on the button itself.

Focus

The shared ring (2px --color-focus-ring, 2px offset) on :focus-visible only. On ink surfaces the ring is gold with an ink gap (--color-focus-ring-on-hero), keeping 3:1 against both the button and the hero.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb ("Close video", "Dismiss"). Loading buttons keep their name and add aria-busy; progress is announced from the form's live region.

Motion

Background and border transition over --duration-fast; active translates 1px. Both vanish under prefers-reduced-motion because the tokens zero the durations. The loading spinner keeps turning: it is status, not decoration.

Touch

Medium (40px) and large (48px) meet the 24px minimum and the 44px comfortable target; the hero signup forces 44px on both control sizes.

Content

  • Labels are verb phrases in sentence case: "Get notified", "Notify me", "Watch the intro", "Unsubscribe". Never "OK", "Submit", "Click here".
  • Say what happens with the object when context does not: "Send a new link" on the expired page, "Try again" in the error toast.
  • Destructive labels name the loss: "Unsubscribe", not "Confirm".
  • Three words or fewer; a label that wraps at 360px is too long.
  • Loading changes the label to progress text only when the wait is explained: "Adding you…", "Unsubscribing…".
