Form field

The wrapper that gives every input the same label, help and error layout.

Overview

The form field is the layout primitive every input uses: label above, control, then error, then help, with --space-1 between parts. It also fixes how optional/required are shown and how counters sit.

Anatomy

  1. Label+ “(required)” / “(optional)” in words.
  2. Control
  3. Error⚠ + sentence; first after the control so it is read next.
  4. Help

Variants

Only for event announcements.

0/280

With help; with optional marker; with counter.

Sizes

Not applicable: Width comes from the column; the control carries the size.

States

Help only.

Responsive behaviour

  • Single column below 768px; two columns above only for short related fields.
  • Label never sits beside the control on phones.

Theming

Label --color-fg-default, help --color-fg-muted, error --color-danger-fg. In the hero these switch to the hero tokens (see text field).

Accessibility

Role and pattern

Layout only; the control carries the semantics. Help and error ids go in aria-describedby (error first).

Keyboard

KeyAction
—Keyboard behaviour belongs to the control.

Focus

No focus of its own.

Labelling

“required” and “optional” are words in the label, not an asterisk; if all fields are required say so once above the form.

Motion

None.

Touch

Label is clickable and focuses the control.

Content

  • Help explains what the value is used for; errors explain how to fix it.
  • One sentence each; no exclamation marks.

  <p class="field__error" id="x-err">How to fix it.</p>
  <p class="field__help" id="x-help">What it is for.</p>
</div>
