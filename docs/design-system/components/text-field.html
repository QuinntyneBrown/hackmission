Text field

One line of text, labelled, with help and errors that say how to fix the problem.

Overview

A text field collects one line of text. On the site it is the email field in the signup form, the one control the whole page exists for. Pair it with form field for label, help and error layout, and see forms for validation timing.

Anatomy

  1. LabelAlways visible or visually hidden, never a placeholder.
  2. Input40px tall, --radius-md, 1px strong border.
  3. ErrorIcon + text, linked with aria-describedby.
  4. HelpMuted, after the error.

Variants

We only email about events.

people
Email, password, search with icon, number with suffix addon.

On ink (hero signup)

One email when registration opens. Unsubscribe anytime.

The hero keeps the input on a light surface; label and help text switch to the hero text tokens.

Sizes

Large is used in the hero signup (and forced to 44px minimum on touch).

States

VariantDefaultHoverFocusDisabledRead-onlyInvalid
Email

Add the end of your email address.

Add the end of your email address.

  • Invalid sets aria-invalid="true", a danger border and an error line; focus moves to the first invalid field on submit.
  • Read-only is used while submitting so the typed email cannot change mid-request.
  • Required is stated in the label when there is more than one field; a single-field form says it in the help text.

Responsive behaviour

  • Full width of its column at every size; the hero row stacks below 640px.
  • inputmode="email" and autocomplete="email" bring the right keyboard and autofill on phones.
  • Font size never drops below 16px so iOS does not zoom on focus.

Theming

Reads --field-* component tokens: surface background, strong border, default text. In the hero, .signup .field__label and .field__help switch to --color-fg-hero / --color-fg-hero-muted and errors to --color-hero-danger (red-300, 5.8:1 on ink).

Accessibility

Role and pattern

Native <input> with a <label for>. Help and error text are tied with aria-describedby; invalid fields set aria-invalid.

Keyboard

KeyAction
TabMoves to the field.
TypingEdits; the browser handles selection and caret keys.
EnterSubmits the form when it is the only field (the signup).

Focus

Shared ring plus a border colour change so the focus is visible even in forced-colors mode.

Labelling

The label is the accessible name; a visually hidden label is still a label (the hero uses one because the button and help text say what the field is). Placeholders are hints, not labels.

Motion

Border colour transitions over --duration-fast.

Touch

40px tall by default, 44px in the hero. The whole label is clickable and focuses the input.

Content

  • Labels are nouns: "Email address", not "Enter your email".
  • Help text says what happens with the value: "One email when registration opens, one reminder before it closes. Unsubscribe anytime."
  • Errors say how to fix it: "Add the end of your email address, like .ca or .com."
  • No placeholder that repeats the label; a placeholder shows a format example at most.
