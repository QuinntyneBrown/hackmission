Dialogs & overlays

When to interrupt, and with what.

Overview

Overlays interrupt. The site uses one: the intro video. Use the smallest overlay that does the job, and a page when the task is long.

When to use which

NeedUse
Play media, confirm a destructive action, a 1–3 field formDialog
Filters, details beside a listDrawer
Small choice anchored to a controlPopover / menu
A name for an iconTooltip
Anything longer than a short formA page

Structure

HackMission in 20 seconds

Backdrop → panel (header, body, footer) over an inert page.
  • One overlay at a time; a menu inside a dialog is fine, a dialog over a dialog is not.
  • Opening does not push history; Esc and the close button both close.

States

  • Open, busy (confirm button loading), failed (error inside the panel), closing (fade).
  • Below 640px dialogs are bottom sheets with the footer sticky.

Responsive behaviour

  • Sheets on phones; centred panels from 640px; drawers full width on phones.

Accessibility

  • role="dialog" aria-modal, labelled; page inert; focus trapped and restored.
  • Tooltips never hold interactive content.
  • Video never autoplays with sound; captions available.

Content

  • Titles name the content or ask the question; buttons name outcomes.
