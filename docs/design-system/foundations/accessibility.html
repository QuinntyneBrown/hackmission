Accessibility

What every page and component promises, and how it is tested.

WCAG 2.2 AAChecked

Overview

The system commits to WCAG 2.2 AA by construction. The checkers enforce the mechanical parts (contrast, labels, names, alt, landmarks, links); each component page's accessibility section answers the rest: role and pattern, keyboard, focus, labelling, contrast, motion, touch.

Commitments

Component page contract

  1. Role and pattern, with the APG pattern linked.
  2. Keyboard map.
  3. Focus: where it starts, where it returns, how the ring looks.
  4. Labelling and announcements.
  5. Contrast pairs with live ratios.
  6. Motion and reduced motion.
  7. Touch targets and hover alternatives.

Testing

  • check_contrast.py on every pair, both themes.
  • check_design_system.py for labels, names, alt, landmarks, headings, links.
  • Manual: Tab through each page; a screen reader on the video dialog, the signup form and a table; zoom to 200% and 400%; emulate reduced motion and forced colours.

Usage

  • When a component is missing a state or an ARIA attribute, fix the system, not the page.
