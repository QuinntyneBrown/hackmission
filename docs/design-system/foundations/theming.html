Theming

Light, dark, OS preference, and how a brand theme overrides semantic tokens only.

Overview

Light is :root; dark is [data-theme="dark"] and, unless the page forces [data-theme="light"], prefers-color-scheme: dark. The two dark blocks are identical. color-scheme is set in each so native controls follow.

Token tiers

TierPrefixExample
Primitive--palette-*, --font-*--palette-gold-500: #E8A33D
Semantic--color-*, --space-*, …--color-accent: var(--palette-ink-900)
Component--btn-*, --field-*--btn-bg: var(--color-accent)

How dark is built

  • Canvas ink-950, surface ink-900, raised ink-800: lighter as it rises.
  • Accent flips from ink to gold; text on accent flips to ink.
  • Status backgrounds become deep tints with light text.
  • The hero deepens to ink-950 so it is distinct from ink-900 surfaces; gold stays gold.

Adding a theme

[data-theme="partner"] {
  color-scheme: light;
  --color-accent: var(--palette-ink-700);
  --color-brand-highlight: var(--palette-gold-700);
  /* override semantic tokens only */
}

Never override primitives or component CSS for a theme.

tokens.json

tokens/tokens.json is a DTCG export generated by scripts/tokens_to_json.py: $type, $value, aliases as {group.token}, theme overrides under $extensions. Regenerate it after any change to tokens.css.

Usage

  • Toggle with the button in the nav or press t; ?theme=dark forces it.
  • Test every component in both themes; the state matrices show both.

Accessibility

  • Both themes pass the same contrast pairs.
  • prefers-contrast: more strengthens borders and muted text; forced-colors hands the ring and borders to system colours.

Tokens

Themes override semantic colour tokens only; see color.
